# PHPサイト外部診断ツール

URLを入力すると、PHPで動くサイトを外側から**非破壊で**確認する Web アプリです。
「PHPサイト外部診断チェックリスト」のうち、外部から自動で確認できる項目を実装しています。

> 外部診断でわかるのは「危険な兆候が見えるか」までで、「安全である」ことの証明にはなりません。
> **対象は自分が管理する、または運用側の許可があるサイトに限ります。**

## 起動

依存パッケージはありません（Node.js 20 以上）。

```bash
npm start            # http://localhost:3000/
npm test             # テスト
```

| 環境変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` / `HOST` | `3000` / `0.0.0.0` | 待ち受けアドレス |
| `MAX_CONCURRENT_SCANS` | `4` | サーバー全体の同時診断数 |
| `SCANS_PER_WINDOW` | `10` | 1 IP あたり 10 分間の診断回数上限 |
| `TRUST_PROXY` | 未設定 | `1` でリバースプロキシの `X-Forwarded-For` を信頼 |
| `ALLOW_PRIVATE_TARGETS` | 未設定 | `1` で内部ネットワーク宛ての診断を許可（ローカル検証用。公開環境では設定しない） |

## 実装したチェック

| 章 | 自動チェック | 手動確認として案内 |
| --- | --- | --- |
| 1. バージョン露出 | X-Powered-By / Server ヘッダー、PHP2Shell（CVE-2026-109618 / 109619）修正版 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 との照合と 8.1 以前の EOL 判定、フォーム送信先・API エンドポイント（最大5件）のヘッダー比較、404 ページのサーバー署名、ディストリのビルド表記検出 | ディストリのセキュリティ情報との照合 |
| 2. 置き忘れファイル | phpinfo 系5ファイル、server-status / server-info、`.env`・設定ファイルのバックアップ、`.git/HEAD`、composer 系ファイル、ディレクトリリスティング、Moodle 検出時の `/admin/phpinfo.php`・`/admin/environment.php`（内容で判定し、秘密の値は表示しない） | — |
| 3. エラー表示 | PHP エラー表示（入力URLの最初のパラメータを `?id[]=1` に配列化した1回のリクエスト）、スタックトレース、DB エラー（受動検出）、OPTIONS の Allow | シングルクォート入力による DB エラー確認（ツールからは送らない） |
| 4. セッション・Cookie | Secure / HttpOnly / SameSite 属性、URL・フォームへのセッション ID 付与 | ログイン前後の ID 変化、ログアウト後の無効化 |
| 5. CMS/ライブラリ | generator タグ、WordPress（readme.html、`?ver=`、REST API のユーザー一覧、プラグイン readme.txt の Stable tag 最大8件）、Moodle（Docs リンクからブランチ判定、4.5 未満は EOL）、jQuery 3.5 未満などの JS ライブラリ、composer.lock の依存一覧 | 各製品の脆弱性 DB との照合 |
| 6. 通信・ヘッダー | HTTP→HTTPS 転送、HSTS（max-age 180日以上）、X-Frame-Options / frame-ancestors、nosniff、CSP（unsafe-inline / unsafe-eval）、TLS（証明書の検証・期限、TLS 1.0 / 1.1 の受け入れ） | SSL Labs による総合評価 |
| 7. 外部ツール | 結果画面にリンク一覧 | — |
| 8. 判定 | 「脆弱なバージョンが見える」「判定不能」「2章のファイルが見える」「3〜6章で問題」「問題なし」を判定表に沿って表示。運用側への確認事項チェックリスト、Markdown コピー・JSON 保存 | — |

判定は「要対応 / 要確認 / 判定不能 / 手動確認 / 情報 / 問題なし」で表示します。
CMS やCookie の判定は入力したURLのページを基準にします。ログインページやパラメータ付きのページを入力すると確認できる範囲が広がります。

## 安全のための設計

- 送るのは GET / HEAD / OPTIONS だけです。攻撃コード、シングルクォート、総当たりは送りません。1回の診断は最大70リクエスト、同時2接続、リクエスト間隔150msです。
- 許可の確認チェックがない診断要求はサーバー側で拒否します。
- SSRF 対策として、名前解決のたびに解決先 IP を検査し、ループバック・プライベート・リンクローカル（クラウドのメタデータを含む）などへの接続を拒否します。ポートは 80 / 443 / 8000 / 8080 / 8443 / 8888 に限ります。
- IP ごとの実行回数制限と、サーバー全体の同時実行数制限があります。

## 構成

```
server.js              HTTP サーバー（静的ファイル + POST /api/scan を NDJSON で逐次返す）
lib/net.js             HTTP/TLS クライアント（SSRF 対策込み）
lib/context.js         リクエスト数・同時接続数の制御とキャッシュ
lib/scanner.js         実行順序と 8 章の総合判定
lib/php-version.js     PHP バージョン抽出と修正版との照合
lib/checks/*.js        1〜6 章の各チェック
public/                画面（HTML / CSS / JS）
test/                  単体テストと、疑似サイトに対する結合テスト
```

修正版のバージョンを変えるときは `lib/php-version.js` の `FIXED_VERSIONS` を編集してください。
